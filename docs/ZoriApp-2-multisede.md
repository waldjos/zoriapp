## Configuración
1. Crear proyecto Firebase independiente para pruebas, Authentication correo/clave y Firestore; no usar datos reales. Configurar en Vercel **Preview** VITE_MULTISEDE_PROJECT_ID, VITE_MULTISEDE_API_KEY, VITE_MULTISEDE_APP_ID, VITE_MULTISEDE_AUTH_DOMAIN y opcional VITE_MULTISEDE_STORAGE_BUCKET. Verificar el dominio permitido. El cliente rechaza expresamente el proyecto histórico.
2. Revisar y probar reglas con emulador antes de aplicar al proyecto de pruebas: firebase deploy --only firestore:rules,storage --config firebase.multisede.json --project ID_DE_PRUEBAS. Nunca usar el ID histórico.
3. Crear primera cuenta en Authentication, activar MFA si disponible y registrar mediante consola Firebase el documento usuarios/UID con rol: superadmin, activo: true. El cliente no puede autoelevar privilegios. Ingresar a /superadmin.
4. Guardar la ficha sugerida periferico_catia, jornada 2026, meta 200, tarifa 120 y renovación 120. Confirmar apertura manual cuando proceda. Añadir también sede de prueba domingo_luciani, con expedientes ficticios. Crear médicos en Authentication y asignar UID desde panel. El registrador solo accede al registro; médico y admin_sede autorizado clínicamente a los datos de su sede. Superadmin no lee pacientes. La creación de cuentas y MFA no están automatizadas.
5. Probar dos usuarios de distintas sedes, uno suspendido, un usuario sin perfil y un superadmin. Intentar consultas/escrituras directas, rutas, exportaciones, cambio de sede desde cliente, registro cerrado, cola local con datos de otra sede y revocación. Probar ambas plataformas móviles. Confirmar que el administrador no lea pacientes. Verificar reglas contra emulador y revisar IAM, API, almacenamiento, CSP y logs.

## Alcance
Registro, búsqueda, tacto, PSA individual desde ficha, estadísticas y exportaciones en rutas activas: referencias a sedes/{sedeId}/pacientes. Perfil de sede validado por servidor. El histórico 2025 queda oculto para Catia. La cola guarda sedeId y el sincronizador verifica pertenencia; fichas antiguas sin sedeId se conservan pero no se reenvían automáticamente. Debe validarse la recuperación tras cerrar la app sin conexión. No se permite cambio de sede de expedientes.

No habilitados: carga PDF, importación PSA por archivo estático, mini jornada con firma fija, SMS masivo. Auditar los endpoints de server.js y OCR, resolver el almacenamiento con acceso autenticado y permisos específicos de laboratorio. No publicar archivos clínicos por rutas estáticas. Falta integrar el logo original de Catia. El año de los módulos heredados todavía es 2026. La UI no sustituye las reglas. Se requiere validar que ninguna ruta heredada se use fuera del ámbito autorizado. No se garantiza compatibilidad con reglas reales ni se han ejecutado pruebas en Firebase.
